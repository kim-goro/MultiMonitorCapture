# 개발용 프롬프트 (Development Prompt)

이 문서는 AI 또는 개발자에게 그대로 전달하여 구현을 지시하기 위한 "지시서"입니다.
아래 내용을 컨텍스트로 고정한 뒤 각 기능을 순차 구현하십시오.

---

## 1. 역할과 목표

당신은 C# WinForms 데스크톱 애플리케이션을 설계·구현하는 시니어 개발자입니다.
"로컬 연결된 다중 모니터 캡처 프로그램"을 실무 수준의 계층형 아키텍처로 구현합니다.

산출물은 단일 실행 파일(exe) 하나이며, 인터넷이 차단된 설비PC에서 동작해야 합니다.

## 2. 절대 제약 (변경 불가)

- 대상 OS: Windows XP SP3 / Windows 10 / Windows 11 (동일 exe 하나로 전부 지원)
- 런타임: .NET Framework 4.0 (Client Profile 아님, 전체 프로파일) 고정
  - 이유: WinXP에서 실행 가능한 마지막 .NET Framework가 4.0
  - async/await 금지, C# 6 이상 문법(널 조건 연산자 ?. 등) 금지
  - 대안: System.Threading, BackgroundWorker, System.Windows.Forms.Timer, Control.BeginInvoke
- 화면 캡처: GDI BitBlt 방식만 사용 (DXGI Desktop Duplication 금지 = Win8+ 전용)
- 런타임 서드파티 NuGet 의존성: 0개 (exe 에 포함되는 종속성 없음)
  - 예외: 빌드 전용 참조 어셈블리 Microsoft.NETFramework.ReferenceAssemblies.net40
    (PrivateAssets=all, exe 에 포함 안 됨). IDE 인텔리센스와 4.0 API 표면 보장용.
- 개발 환경: VSCode + C# 확장 + .NET SDK(dotnet)
  - 빌드는 dotnet build 로 수행한다 (구형 v4.0 MSBuild 는 PackageReference 미지원이라 사용 안 함)
  - WinForms 비주얼 디자이너가 없으므로 .Designer.cs 는 수기 작성
- 실행 권한: 표준 사용자 권한(asInvoker), 관리자 권한 요구 금지
- 인터넷/네트워크 통신 코드 전면 금지 (오프라인 설비PC)

## 3. 아키텍처 규칙

- 계층 분리: Api / Domain / Service / Infrastructure + Presentation(MVP) + Designer(화면)
  - 상세는 docs/02_아키텍처설계.md 를 따른다
- 의존성 방향: Designer/Presentation -> Api -> Service -> Domain <- Infrastructure
  - Domain 은 어떤 계층에도 의존하지 않는다 (순수 모델/인터페이스)
  - Infrastructure 는 Domain 의 인터페이스를 구현한다
- 의존성 주입: 외부 DI 컨테이너 없이 Program.cs 의 합성 루트(Composition Root)에서 수동 조립
- 메인 스크립트(Program.cs)에서 컨트롤을 즉석 생성 금지
  - 캡처 타일은 재사용 UserControl 로 정의하고, 생성은 CaptureTileFactory 로 캡슐화
- 디자인 패턴 적용: MVP, Repository, Factory, Strategy, Command, Observer(이벤트)
- P/Invoke 는 NativeMethods 클래스 한 곳에만 격리

## 4. 코딩 규칙

- 주석은 간단한 한 줄 설명 위주, 주석 안에 마크다운 문법(#, *, - 등) 사용 금지
  - 예: // 주 모니터를 제외한 화면 목록을 반환한다
- 모든 GDI/네이티브 자원(Bitmap, Graphics, HDC)은 using 또는 try/finally 로 반드시 해제
- 예외는 삼키지 말고 로깅 후 사용자에게 안전하게 알림 (프로그램/PC 다운 금지)
- 단일 인스턴스만 실행되도록 Mutex 사용
- 스레드에서 UI 접근 시 반드시 Control.BeginInvoke 사용

## 5. 구현 순서 (권장)

1. 프로젝트 골격 + csproj(.NET 4.0, WinExe) + 매니페스트(asInvoker) + 빌드 스크립트
2. Domain 모델/인터페이스 정의
3. Infrastructure: GDI 캡처, 모니터 열거, 설정 저장소
4. Service: 캡처/모니터/설정/주모니터 서비스
5. Api: 파사드 및 계약
6. Designer: ControlForm, CaptureTile(UserControl), AboutForm, TrayComponent
7. Presentation: Presenter 연결 (MVP)
8. 기능 1~7 순차 완성 및 각 기능별 수동 테스트
9. 보안 체크리스트(docs/03) 점검 후 릴리스 빌드

## 6. 완료 기준 (Definition of Done)

- 관리자 권한 없이 동작, 시스템 설정 임의 변경 없음(주 모니터 OS 변경은 명시적 확인 후에만)
- docs/03 보안 체크리스트 전 항목 통과
