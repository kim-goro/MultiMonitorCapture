# 아키텍처 설계 (Architecture Design)

목표: 독립성, 모듈화, 실무 적용 가능한 계층 분리와 디자인 패턴 적용.
스택: C# / WinForms / .NET Framework 4.0

---

## 1. 계층 개요

의존성 방향 (화살표는 "의존한다"):

  Designer(화면) ─▶ Presentation(MVP) ─▶ Api(파사드) ─▶ Service ─▶ Domain
                                                              ▲
                                              Infrastructure ─┘ (Domain 인터페이스 구현)

- Domain: 순수 모델/열거형/인터페이스. 외부 의존 0. (핵심, 가장 안쪽)
- Service: 업무/응용 로직. Domain 인터페이스에만 의존. OS/UI 비의존.
- Infrastructure: OS/Win32/파일 등 실제 구현. Domain 인터페이스를 구현.
- Api: UI가 사용하는 파사드/계약. Service 를 조합해 상위 시나리오 제공.
- Presentation: MVP 의 Presenter. View 인터페이스와 Api 에만 의존.
- Designer: Form/UserControl(.Designer.cs). View 인터페이스 구현.

Composition Root(Program.cs)에서 Infrastructure 구현을 Service 에 주입해 조립한다.

## 3. 핵심 도메인 인터페이스 (Domain/Abstractions)

주석 안에 마크다운 문법 사용 금지.

```csharp
// 화면을 캡처하는 최소 계약
public interface IScreenCapturer
{
    // 지정한 화면 영역을 비트맵으로 캡처한다. 호출자가 Dispose 책임을 진다.
    Bitmap Capture(Rectangle bounds);
}

// 물리 모니터 목록을 제공한다
public interface IMonitorProvider
{
    // 현재 연결된 모니터 정보를 열거한다
    IList<MonitorInfo> GetMonitors();
}

// 설정 영속화 계약(저장소 추상화)
public interface ISettingsRepository
{
    AppSettings Load();
    void Save(AppSettings settings);
}

// OS 주 모니터 변경 계약(선택 기능, 확인 후에만 호출)
public interface IPrimaryMonitorController
{
    // 지정 모니터를 OS 주 모니터로 설정한다. 성공 여부 반환.
    bool SetPrimary(MonitorInfo monitor);
}
```

## 4. 적용 디자인 패턴

- MVP (Model-View-Presenter)
  - View(Form/UserControl)는 IControlView / ICaptureTileView 인터페이스만 노출.
  - Presenter 가 Api 를 호출하고 View 를 갱신 → 로직과 화면 분리, 테스트 용이.
- Repository
  - 설정 저장을 ISettingsRepository 로 추상화(IniSettingsRepository 구현).
- Factory
  - CaptureTileFactory 가 타일 생성/초기화를 캡슐화(메인 스크립트 즉석 생성 금지 규칙 충족).
- Strategy
  - IScreenCapturer 로 캡처 방식을 교체 가능하게. 현재는 GDI 구현만.
- Command
  - 트레이 메뉴 동작을 ICommand 유사 객체로 캡슐화(Execute) → 메뉴와 동작 분리.
- Observer(이벤트)
  - CaptureService 가 프레임 준비 이벤트를 발행, Presenter 가 구독하여 UI 갱신.
- Facade
  - AppFacade 가 여러 서비스를 묶어 UI 가 단순 API 로 사용.

## 5. 스레딩 모델

- CaptureService 는 전용 백그라운드 스레드 또는 BackgroundWorker 로 캡처 루프 수행.
  - .NET 4.0 이므로 async/await 미사용. Thread + ManualResetEvent 또는 Timer 사용.
- 캡처 결과는 CaptureFrame 이벤트로 발행 → Presenter 가 Control.BeginInvoke 로 UI 반영.
- 타일마다 최신 프레임 1장만 유지(더블 버퍼링), 이전 Bitmap 즉시 Dispose.
- 컨트롤창 숨김 시 캡처 루프 일시정지 옵션으로 CPU 절감.

---

## 6. 자원 관리 원칙 (누수 방지)

- Bitmap, Graphics, HDC, HBITMAP 은 using/try-finally 로 항상 해제.
- P/Invoke 로 얻은 DC 는 ReleaseDC/DeleteDC, 객체는 DeleteObject 로 해제.
- NotifyIcon, Timer, Thread 는 종료 시 Dispose/정지.
- 폼 Dispose 체인에서 자식 컨트롤과 오버레이 리소스 모두 정리.

## 7. 화면(Designer) 설계 요약

- ControlForm
  - TableLayoutPanel(격자) + 상태바(선택). 빈 영역 ContextMenuStrip("주 모니터 설정").
  - FormClosing 에서 숨김 처리(FR-8).
- CaptureTile (UserControl)
  - PictureBox/PbPreview(영상) + 상단 좌측 번호 라벨(오버레이) + 하단 바(이름 라벨 + "..." 버튼).
  - OnPaint 에서 노란 테두리(호버) 및 클릭 원(오버레이) 렌더.
  - MouseEnter/Leave, MouseDown 로컬 이벤트 처리(전역 훅 없음).
- AboutForm
  - 정보 표시(FR-9). 읽기 전용.
- TrayComponent
  - NotifyIcon + ContextMenuStrip. Command 객체로 각 메뉴 동작 위임.
- CaptureTileFactory
  - 모니터 목록을 받아 타일을 생성하고 격자에 배치하는 로직 캡슐화.

## 8. 빌드/배포

- csproj: TargetFrameworkVersion v4.0, OutputType WinExe, AnyCPU.
- 빌드: build/build.ps1 에서 dotnet build 호출(Release, 단일 exe).
- 빌드 전용 참조 어셈블리(Microsoft.NETFramework.ReferenceAssemblies.net40, PrivateAssets=all)로
  타기팅 팩 없이도 4.0 표면을 정확히 참조한다. exe 에는 포함되지 않는다.
- 런타임 서드파티 의존 0 → ILMerge 불필요, exe 단독 배포.
- 매니페스트로 asInvoker 고정. DPI 인식은 시스템 수준(XP 호환 위해 per-monitor 미사용).
