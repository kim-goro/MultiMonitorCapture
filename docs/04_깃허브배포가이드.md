# GitHub 업로드 및 공개배포 가이드

대상: GitHub Desktop(GUI)로 소스 업로드 + GitHub Releases 로 exe 공개배포
전제: 아직 업로드 전 상태. 오프라인 설비PC용 도구이나, 소스/릴리스는 공개 예정.

---

## 1. 업로드 전 준비 (필수 점검)

- [ ] 비밀정보 커밋 금지: 비밀번호, 사내 IP, 인증서(.pfx), API 키, 내부 문서 미포함
- [ ] .gitignore 준비(빌드 산출물/사용자 설정 제외, 아래 3장)
- [ ] LICENSE 파일 확정(라이선스 선택은 5장, 결정 후 추가)
- [ ] README.md 작성(프로그램 설명/스크린샷/사용법/호환 OS/주의사항)
- [ ] 취급 주의 고지: "화면 실시간 캡처 도구" 특성 명시(민감정보 노출 주의)
- [ ] 저장소 공개 범위 결정: Public(공개) vs Private(비공개 후 전환)

## 2. GitHub Desktop 으로 업로드하는 절차

1. GitHub Desktop 설치 후 GitHub 계정으로 로그인
   (File > Options > Accounts > Sign in)
2. 로컬 프로젝트를 저장소로 추가
   - File > Add local repository > 프로젝트 폴더(MultiMonitorCapture) 선택
   - "create a repository" 안내가 나오면 Create a repository 클릭
3. 저장소 정보 입력
   - Name: MultiMonitorCapture
   - Description: 다중 모니터 실시간 캡처 도구 (WinXP/10/11)
   - Git ignore: Visual Studio 템플릿 선택(또는 3장 파일 사용)
   - License: 선택(5장에서 결정한 값). 미정이면 나중에 파일로 추가
4. 첫 커밋
   - 좌측 Changes 탭에서 변경 파일 확인
   - Summary 에 "chore: initial project skeleton and docs" 입력 후 Commit to main
5. 원격 공개(Publish)
   - 우측 상단 Publish repository 클릭
   - Keep this code private 체크 해제하면 Public 공개, 체크하면 Private
   - Publish repository 클릭하면 github.com 에 업로드 완료
6. 이후 변경 반영
   - 파일 수정 > Changes 에서 Commit > 우측 상단 Push origin 으로 원격 반영

## 3. .gitignore 권장 내용 (.NET / Visual Studio)

프로젝트 루트에 .gitignore 파일로 저장. 빌드 산출물과 사용자별 파일은 올리지 않는다.

```
# 빌드 산출물
bin/
obj/
# Visual Studio / Rider 로컬 설정
.vs/
*.user
*.suo
# 배포/임시
*.log
*.tmp
# 로컬 설정(런타임 생성)
settings.ini
```

주의: exe 는 소스 트리(bin)에 커밋하지 말고 Releases 에 첨부한다(4장).

## 4. exe 공개배포 (GitHub Releases)

소스는 커밋으로, 실행 파일은 Release 자산으로 배포하는 것이 표준이다.

1. 릴리스용 빌드 생성(Release, .NET 4.0, 단일 exe)
2. github.com 저장소 > Releases > Draft a new release
3. 태그 지정: v1.0.0 (버전과 일치, 4자리 예: v1.0.0)
4. 제목/설명 작성
   - 변경 내역(Changelog), 지원 OS(WinXP SP3/10/11), 실행 요구사항(.NET Framework 4.0)
   - 취급 주의 문구 재고지
5. 자산 첨부: MultiMonitorCapture.exe 업로드
   - 무결성용으로 SHA-256 해시값을 설명에 함께 기재(위변조 확인용)
6. Publish release

무결성 해시 생성(PowerShell):
```
Get-FileHash .\MultiMonitorCapture.exe -Algorithm SHA256
```

## 5. 공개배포 시 준수사항 / 결정 필요 사항

### 5.1 라이선스 (필수 결정)
- 오픈소스 공개 시 LICENSE 파일이 없으면 "기본적으로 모든 권리 보유"가 되어
  타인이 합법적으로 사용/수정/재배포할 수 없다. 공개배포라면 라이선스 명시 권장.
- 대표 선택지
  - MIT: 가장 관대. 출처 표기만 요구. 상업적 사용/수정/재배포 자유. (권장 기본)
  - Apache-2.0: MIT 유사 + 특허 보호 조항 포함. 기업 친화적.
  - GPL-3.0: 파생물도 동일 라이선스로 공개해야 함(카피레프트). 강한 공유 강제.
- 결정 후 저장소 루트에 LICENSE 파일 추가, README 상단에 배지/문구 표기.

### 5.2 제3자 구성요소 고지
- 본 프로젝트는 서드파티 의존성 0 지향이므로 재배포 라이선스 부담이 적다.
- .NET Framework 4.0 은 사용자 OS 구성요소(직접 재배포하지 않음). README 에
  "실행에 .NET Framework 4.0 필요"만 안내한다(XP 는 별도 설치 필요할 수 있음).

### 5.3 코드 서명 (선택, 사용자 신뢰성 관련)
- 미서명 exe 는 Windows SmartScreen/Defender 가 "알 수 없는 게시자" 경고를 띄울 수 있다.
- 서명하면 게시자 신원과 위변조 여부가 보장되어 경고가 줄어든다.
- 다만 코드 서명 인증서(OV/EV)는 유료이며 발급에 신원확인이 필요하다.
- 오프라인 사내 배포가 주 목적이면 필수는 아니며, 해시 공개(4장)로 무결성을 보완할 수 있다.

### 5.4 개인정보/보안 고지
- 화면 캡처 도구 특성상 README/About 에 다음을 명시한다.
  - 캡처 영상은 로컬 메모리에만 존재하며 저장/전송하지 않음
  - 민감 화면 노출 주의, 사용자 책임 하에 사용
- 저장소에 사내 정보/스크린샷의 민감 영역이 노출되지 않도록 이미지 검수.

### 5.5 버전/변경관리 준수
- 태그(vX.Y.Z)와 어셈블리 버전, 제목표시줄 표기(FR-1.2)를 일치시킨다.
- 큰 업데이트마다 docs/03 보안 체크리스트 점검 기록을 남긴다.

## 6. 권장 저장소 구성(공개용)

```
MultiMonitorCapture/
├─ README.md          프로그램 소개/사용법/호환성/주의사항
├─ LICENSE            선택한 오픈소스 라이선스
├─ .gitignore         3장 내용
├─ CHANGELOG.md       버전별 변경 이력(선택)
├─ src/               소스 코드
├─ docs/              설계/명세/보안 문서
└─ build/             빌드 스크립트
```
